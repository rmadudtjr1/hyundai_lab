3.3Deep Research, Canvas, 이미지

Deep Research

  1. 왼쪽 메뉴 Deep Research
  2. Sources에서 출처 고르기 (사내 문서, Google 검색 추가 가능)
  3. 질문 입력 → 제시된 연구 계획을 읽고 고치기
  4. Start Research

몇 분 뒤 인용이 달린 보고서와 1~2분 길이 오디오 요약이 나옵니다. Standard는 하루 3회라 질문을 다듬은 뒤 실행합니다.

Canvas (문서·슬라이드 편집기)

  1. 도구 메뉴의 Canvas를 고르거나 “문서로 만들어 줘”라고 요청
  2. 오른쪽 편집기에서 직접 고치거나, 문장을 골라 Gemini에게 다시 쓰게 함
  3. 내보내기: 문서는 Google Docs·DOCX·PDF, 슬라이드는 Google Slides·PowerPoint·PDF

Canvas는 모바일에서 열리지 않고, 대화를 공유받은 사람도 열 수 없으니 내보낸 파일로 전달합니다.

도구 메뉴의 Generate an image, Generate a video로 교육용 그림이나 짧은 영상을 만들 수 있습니다. Standard 한도는 하루 이미지 5장, 영상 2개입니다.

3.4모바일 앱과 음성

  • 모바일 앱(Google Gemini Enterprise, iOS·Android, 2026-06 정식 출시): 웹 앱에 나오는 QR 코드나 관리자가 준 링크로 연결합니다. 카메라로 찍은 사진을 바로 질문할 수 있고, 음성으로 묻고 답을 소리로 들을 수 있습니다. 에이전트도 실행됩니다.
  • 웹 음성 입력(2026-09 정식 출시): 입력창의 마이크 → 말하기 → 정지 → 받아쓴 글을 고친 뒤 보내기. 녹음은 저장되지 않습니다.
  • 메일 발송처럼 밖으로 나가는 동작은 모바일에서도 사용자가 확인해야 실행됩니다.
현장 활용 예: 설치·서비스 기사가 고장 표시창이나 부품 사진을 찍어 “이 코드가 뭐고 1차 조치는?”이라고 묻기. 단, 고객 이름·연락처가 찍힌 화면은 찍지 않습니다.

3.5보안 수칙과 하루 한도

회사 계정으로 쓰는 Gemini Enterprise에 넣은 질문과 결과는 Google 모델이나 다른 고객의 모델 학습에 쓰이지 않습니다(공식 FAQ). 그래도 아래 수칙은 지킵니다. 관리자는 민감 문구 차단, 채팅 보관 기간 같은 설정으로 한 번 더 막습니다.

해도 됩니다

  • 업무 문서, 사내 규정, 공개된 자료 분석
  • 회의 메모에서 개인 평가를 지운 뒤 정리
  • 고객사 이름을 “A사”로 바꾼 뒤 제안서 초안
  • 결과를 원본과 대조한 뒤 보고

하지 않습니다

  • 주민등록번호, 건강 정보, 계좌·카드 번호, 비밀번호 입력
  • 개인 Gmail 등 회사 밖 AI 서비스에 회사 자료 넣기
  • 민감 정보가 든 대화를 링크로 공유 (공유 시점 내용이 그대로 보임)
  • AI 답을 확인 없이 고객에게 그대로 발송

Antigravity 활용

방식 시연·실습권장 70분결과물 서비스 현황 대시보드 페이지데이터 10_Antigravity_실습
채팅이 “찾고 답하는 도구”라면 Antigravity는 “만드는 도구”입니다. 엑셀·CSV를 주고 말로 요청하면 계획을 세워 보여 주고, 승인하면 대시보드나 작은 업무 도구를 만들어 줍니다. 일반 사용자가 데이터를 가져오는 4가지 방식을 익히고, Databricks 연동은 강사 시연으로 봅니다.

9.1시작 조건

  • Gemini Enterprise Standard·Plus에 AI 개발자 도구로 포함되어 있습니다(2026년 8월 정식 출시). 관리자가 AI developer tools를 켜야 합니다.
  • Antigravity 앱 설치 후 로그인 화면에서 회사 계정(Business account) > Continue with Google Cloud를 고릅니다.
  • Standard는 사용자당 월 $10 상당의 개발자 도구 크레딧이 포함됩니다.
  • 고객 코드와 자료는 기본 모델 학습에 쓰이지 않습니다.

9.2일하는 방식: 말하기 → 계획 확인 → 실행 → 검토

  1. 말하기: 자료 위치, 만들 것, 결과 형태, 주의할 점을 적습니다 (05장 5요소 그대로).
  2. 계획 확인: Antigravity가 구현 계획(Implementation Plan)을 보여 줍니다. 읽고 고칠 점을 말합니다. 여기서 대부분의 실수가 걸러집니다.
  3. 실행: 승인하면 파일을 만들고 고칩니다. 사람 검토 모드에서는 중요한 동작마다 확인을 묻습니다.
  4. 검토: 결과 화면을 열어 숫자를 원본과 대조하고, 고칠 점을 이어서 말합니다.

9.3데이터 활용 4가지

방식흐름언제이 장에서
① 파일 업로드형시스템에서 엑셀·CSV 내려받기 → 화면에서 파일 선택 → 브라우저 안에서만 분석·차트가끔 보는 분석, 자료가 PC 밖으로 나가면 안 될 때실습 1
② 예약 자동 갱신Power Automate 예약 실행 → SharePoint 고정 폴더에 저장 → 화면이 최신 파일을 자동 조회매일·매주 같은 현황판실습 2
③ 에이전트 결과 활용사내 조회 에이전트(07장) 결과를 표로 받아 저장 → ①·② 방식으로 화면에 표시여러 시스템을 묻는 일은 에이전트가, 보여 주기는 화면이실습 1에 포함
④ Databricks 연동정기 갱신 테이블 → (2027년) 포털에서 데이터 조회 → 갱신 주기를 고르면 화면에 자동 반영전사 표준 데이터, 대량·정기 데이터강사 시연
실습 1 · 파일 업로드형 + 에이전트 결과 25분 · 10_Antigravity_실습
  1. Antigravity에서 새 프로젝트를 열고 작업 폴더로 10_Antigravity_실습을 고릅니다.
  2. 아래 프롬프트를 넣고, 구현 계획이 나오면 “데이터를 외부로 보내지 않는다”가 들어 있는지 확인한 뒤 승인합니다.
  3. 만들어진 index.html을 브라우저로 열어, KPI 숫자를 CSV 합계와 대조합니다.
  4. “평균 도착 30분 초과 지역은 빨간색으로”처럼 한 가지를 고쳐 달라고 이어서 말합니다.
이 폴더의 '일일AS현황_20261023.csv'와 '에이전트결과_재발현장_상위10.csv'로 서비스 현황 대시보드 한 페이지(index.html)를 만들어 줘.
- 위: 오늘 접수, 처리 완료, 미처리, 승객 갇힘 4개 숫자
- 가운데: 지역별 접수(완료/미처리 구분) 막대, 지역별 평균 도착 시간 막대(30분 초과는 강조)
- 아래: 재발 상위 현장 표, 리모델링 제안 대상은 표시
- 화면에서 다른 날짜 CSV를 골라 다시 그릴 수 있게 파일 선택 버튼도 넣어 줘
조건: 데이터는 브라우저 안에서만 처리하고 외부 서버로 보내지 마. 외부 라이브러리는 쓰지 마.
만들기 전에 구현 계획을 먼저 보여 줘.
실습 2 · 예약 자동 갱신 15분

실제 운영에서는 Power Automate가 AS 시스템 파일을 매일 SharePoint 고정 폴더에 저장하고, 그 폴더를 PC와 동기화해 둡니다. 실습에서는 같은 폴더에 새 CSV를 넣는 것으로 대신합니다.

  1. 실습 1의 대시보드에 “폴더에서 가장 최근 날짜의 일일AS현황 파일을 자동으로 읽어 줘”를 추가 요청합니다.
  2. /schedule로 예약 작업을 만듭니다: 이름 “AS 현황 갱신”, 매일 08:00, 프롬프트 “폴더의 최신 일일AS현황으로 대시보드를 갱신하고, 미처리 5건 이상 지역이 있으면 요약을 알려 줘”.
주의 예약 작업은 PC가 켜져 있고 Antigravity 앱이 실행 중일 때만 돌고, Flash 모델로 실행됩니다. 24시간 무인 실행이 필요하면 과정 2의 Cloud Run 자동화로 넘깁니다.
강사 시연 · Databricks 연동 15분

Antigravity에는 Databricks 전용 연결이 기본으로 들어 있지 않습니다(2026년 10월 기준, MCP 스토어 목록에 없음). 시연은 사전에 연결을 구성해 둔 환경에서 합니다.

단계시연 내용
1. 연결Settings → Customizations → Installed MCP Servers → Add MCP에서 Databricks 쪽 MCP 서버를 등록 (사전 구성, 접속 권한은 조회 전용 계정)
2. 조회“수주 집계 테이블에서 지역별 최근 4분기 달성률을 가져와 줘” → 실행할 SQL을 계획에 보여 주고 승인 후 조회
3. 화면실습 1 대시보드의 데이터 출처를 CSV에서 테이블 조회로 바꿈
4. 갱신 주기테이블 갱신 주기(예: 매일 06시)에 맞춰 예약 작업으로 다시 조회

2027년 사내 포털이 열리면 ④는 “포털에서 테이블과 갱신 주기를 고르면 화면에 자동 반영”되는 구조가 목표입니다. 그 전까지는 ①~③으로 시작하고, Databricks 연결 방식(관리형 MCP, BigQuery 페더레이션 등)은 IT 부서와 PoC로 정합니다.

  • 구현 계획에서 외부 전송, 파일 삭제, 설치 명령이 있으면 이유를 묻고 승인한다
  • 결과 화면의 숫자는 원본과 대조한 뒤 공유한다
  • 잘된 방식은 /learn으로 규칙에 남겨 다음 작업에 재사용한다
